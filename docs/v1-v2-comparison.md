# V1 and V2 preliminary validation

V1 uses exact stop matching and confirmed route-specific mappings; V2 adds the existing experimental route-conditioned fuzzy matching. Both train on October 1–21. We reserve October 25–31 for final testing; October 22–24 is development validation. V2's index built for this comparison contains the daily sample-count baseline; it is not yet the scheduled-service-normalized API model.

The provisional common target is constructed using V2's matching rules on validation tickets. The same target is used for both models, but it is not independent: incorrect fuzzy matches can become labels and favor V2. The comparison includes only segment/hour/day rows with at least one V2-matched ticket and reports mean absolute error on rows where both models return a prediction. Report availability separately; do not treat missing predictions as zero. It omits zero-observation days and scores ticket counts conditional on an observation, not actual occupancy, per-bus crowding, or end-to-end journeys. Counts are grouped by ticket-creation hour as a boarding approximation, whose validity is unknown. The result is exploratory, not sufficient to select a winning crowding model.

Before final testing, review a representative, ticket-weighted sample of V2-only stop matches and obtain independent segment/time ground truth where possible. Freeze matching decisions, evaluation targets and metrics before using the final week. Review errors by route, day and time and coverage, including cases where only one model predicts. If ground truth cannot be obtained, describe conclusions as ticket-sample pattern stability, not crowding accuracy.
